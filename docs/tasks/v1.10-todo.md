## Objective

Two features that together let users compose larger workflows from existing trees:

- **Phase A — FB3 Tab reordering:** browser-style drag-to-reorder tabs.
- **Phase B — FR2 Cross-tree Move/Copy:** select N nodes in one tab, pick a destination tab, choose Move or Copy.

Highest-risk release in the v1.8–v1.10 batch. Phase A lands first so Phase B's destination picker reflects user-meaningful tab order. Phase B is the first action since v1.7.1's unified-timeline ship that *intentionally* mutates two trees in a single snapshot.

## Resolved Spec Decisions

| # | Question | Decision |
|---|---|---|
| 1 | **Phase A library** | `@dnd-kit/sortable` + `@dnd-kit/core` (~25 KB gz). Picked over native HTML5 DnD for accessibility (keyboard reorder, screen reader support) and touch handling. |
| 2 | **Phase A drag handle** | Entire tab body, except the × close button and an active rename input. Stop event propagation on those before DnD library sees them. |
| 3 | **Phase A history** | One `withSnapshot` push per drop. Cancelled drag (drop outside, Esc) does not push. |
| 4 | **Phase B surface** | Toolbar "Move / Copy" button + modal with destination dropdown + Move\|Copy radio + summary + validation. Chosen over context menu / drag-to-tab. |
| 5 | **Move semantics** | Preserve node + edge IDs; remove from source; add to destination. Boundary edges (selected → unselected) silently dropped (v1.5 precedent). Single `withSnapshot`. |
| 6 | **Copy semantics** | Regenerate IDs (reuse v1.5 `duplicateSelection` ID-mapping logic, extracted to a shared `regenerateIds` helper). Source unchanged. Destination receives new-ID nodes + edges. |
| 7 | **After-action selection** | `activeTreeId` switches to destination; transferred (Move) or copied (Copy) node IDs become the new selection. |
| 8 | **Validation rules** | V1 Root conflict (selection contains Root + dest already has Root); V2 cycle (selection contains SubTree referencing destination); V3 empty selection (button disabled); V4 single-tree document (button disabled). Validation runs in the modal; store action assumes valid input. |
| 9 | **Boundary edge handling** | Always silently dropped. No "smart merge" toggle. Modal summary shows the dropped count. |
| 10 | **Move that empties source tree** | Allowed (matches "+ button creates empty tree" precedent from v1.4 T11). |
| 11 | **Move with SubTree referencing source** | Allowed; reference text doesn't change (it's by tree name, not ID). The SubTree now lives in a different tree but still resolves correctly. Verify in test. |

## Out of Scope

- Drag-selection-onto-tab as Move trigger.
- Cross-document (cross-file) move/copy.
- Smart-merge of edges to unselected nodes.
- Move/Copy keyboard shortcut (e.g., Ctrl+Shift+M) — defer until requested.
- Visualizing the impact via preview before Confirm.

## Phase B — Move/Copy (FR2)

### T4 — Pure `moveCopySelection` + extract `regenerateIds` helper ✅ (commit `2dd84eb`)

**Description:** New pure function in `src/core/model/operations.ts`. Compose existing patterns: filter source, append to destination, drop boundary edges. For Copy mode, reuse v1.5 `duplicateSelection`'s ID-mapping by extracting it into a shared `regenerateIds(nodes, edges)` helper.

**Signature:**
```ts
export interface MoveCopyInput {
  sourceTree: Treeish;
  destTree: Treeish;
  selectedNodeIds: ReadonlySet<string>;
  mode: 'move' | 'copy';
}

export interface MoveCopyResult {
  sourceTree: Treeish;
  destTree: Treeish;
  transferredNodeIds: string[];
  droppedEdgeCount: number;
}

export function moveCopySelection(input: MoveCopyInput): MoveCopyResult;
```

> **Deviation (commit `2dd84eb`):** signature is generic `moveCopySelection<S, D extends Treeish>` (not bare `Treeish`) so the store keeps `BTTreeDef` typing (id/name) without casts; `MoveCopyInput`/`MoveCopyResult` are generic interfaces. `Treeish` is now exported. Same runtime shape as spec.

**Acceptance criteria:**
- [x] `regenerateIds` extracted from existing `duplicateSelection`; `duplicateSelection` updated to call it. Existing tests still pass (46 operations tests green).
- [x] `moveCopySelection` Move: source has selected nodes/edges removed; dest has them appended; boundary edges dropped from BOTH trees; `transferredNodeIds` = original IDs.
- [x] `moveCopySelection` Copy: source unchanged (by reference); dest has new-ID nodes + edges (via `regenerateIds`); `transferredNodeIds` = new IDs.
- [x] Both modes preserve node positions verbatim.
- [x] Both modes preserve connection `order` field.
- [x] Returns input source/dest by reference when nothing resolves after filtering (Copy always returns source by reference).
- [x] No mutation of inputs (JSON round-trip assertion).

**Risk:** `regenerateIds` extraction is a refactor of v1.5's duplicate code path. Run v1.5's existing tests verbatim before and after extraction to confirm no behavior change. → **Verified: 46 operations tests green post-refactor.**

**Verification:**

- [x] Existing `duplicateSelection` tests still pass.
- [x] `npm run test:ci` green; unit 410 → 419 (+9).

**Dependencies:** None.

**Files:** `src/core/model/operations.ts`, `tests/unit/core/model/operations-move-copy.test.ts` (new), `tests/unit/core/model/operations.test.ts` (verify duplicate tests still green after refactor).
