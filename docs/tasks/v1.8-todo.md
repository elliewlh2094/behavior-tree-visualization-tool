**FB5 finding (surfaced at T5):** With `NODE_HEIGHT = 75px` (3 grid rows), a two-line `text-sm` label + kind badge measures ~60px — under the 75px floor — so wrapping to two lines does **not** grow the node, and `useApplyLayout` feeds 75px for every node into `computeTreeLayout`, leaving the per-row-pitch path inert in practice. The primary fix (long names wrap instead of truncating) works; the secondary "grows by one grid row to 100px" behavior in AC7.1/AC7.2 and ship-smoke 6 does not trigger for ≤2-line labels. The `nodeHeights` plumbing remains correct and unit-tested (synthetic heights) and would engage if node content ever exceeds 75px (larger fonts/themes). **Needs a decision in T6:** soften the AC7/smoke-6 wording, or change the node base height (out of T7's stated scope).

## T7 — BTNode label wrap + per-node layout heights (FB5)

**Description:** Let long node names wrap onto a second line and grow the node by one grid row (25 px). Keep default 75 px height for names that fit on one line. Truncate only when the name overflows two lines. Touches three files: `BTNode.tsx` for the label CSS + dropping the fixed `height` style, `tree-layout.ts` for an optional per-node-heights map in `LayoutOptions`, and `useApplyLayout.ts` to feed xyflow's existing `measured.height` through to the layout call.

**Acceptance criteria:**
- [x] `BTNode.tsx` label `<div>` no longer carries the `truncate` class; gains `line-clamp-2 break-words text-center`. (Spec AC7.3 truncation source)
- [x] `BTNode.tsx` wrapper no longer sets a fixed `height: NODE_HEIGHT` inline style; height auto-sizes between 75 px (one line) and 100 px (two lines) via `minHeight: NODE_HEIGHT` + `line-clamp-2`. `width: NODE_WIDTH` is preserved. (Spec AC7.1, AC7.2)
- [x] `tree-layout.ts` `LayoutOptions` gains optional `nodeHeights?: Map<string, number>`. Per-row pitch becomes `max(nodeHeights.get(id) ?? nodeHeight, ...) + gapY` (computed per depth in `rowMaxHeight`/`rowY`). (Spec AC7.6)
- [x] When `nodeHeights` is absent, `computeTreeLayout` output is byte-identical to v1.7.1. Verified by re-running the existing 10 `tree-layout.test.ts` tests (all green), not a new snapshot.
- [x] `useApplyLayout.ts` reads each xyflow node's `measured.height` (post-paint) into a `Map<string, number>` and passes it through to `computeTreeLayout`. (Spec AC7.7)
- [x] ~~Root centering in `useApplyLayout.ts` uses Root's `measured.height`~~ — **N/A (deviation):** T2 already replaced `setCenter`-based root centering with `fitView`, so there is no root-centering code left in `useApplyLayout.ts`. `fitView` frames the whole post-layout bounding box, which already accounts for grown nodes. Moot AC.
- [x] No change to `src/store/bt-store.ts`, `operations.ts`, or the file format. Heights are runtime measurements only — never persisted.

**Risk:**
- xyflow's `node.measured.height` is populated after the first paint, so the very first Layout press on a freshly opened tree may use the default-height fallback for unmeasured nodes. Acceptable: the next press uses real measurements. Document this behavior if any user-visible jitter surfaces during manual smoke.
- `line-clamp-2` is a webkit-prefixed property; verify it works in the project's supported browsers (Chrome/Edge/Firefox/Safari — all currently support it). No fallback needed.
