## Out of Scope

- Renaming a SubTree from any surface other than the tab (single rename surface is the post-B1 invariant).
- Image export, Move/Copy, tab reordering — those are v1.9/v1.10.
- Touching `BTNode.tsx` for any kind-specific rendering.
- Changing the PWA strategy beyond the documented opt-out script.

## T2 — Layout button uses `fitView` (FB1)

**Description:** In `src/hooks/useApplyLayout.ts`, replace the `setCenter(rootX, rootY) + getZoom()` calls with `fitView({ padding: 0.2, duration: 200 })`. `fitView` is already destructured from `useReactFlow()` in `Canvas.tsx:101` and used on tab switch — Layout adopts the same call.

**Acceptance criteria:**
- [ ] Layout on a multi-node tree centers and zooms so the bounding box of all nodes is visible with ~10% padding. (Spec AC4.1)
- [ ] Layout on a single-node tree centers without zooming above 1.0×. (Spec AC4.2)
- [ ] After Layout, the per-tab viewport store reflects the new viewport (already wired via `onViewportChange`). (Spec AC4.3)
- [ ] Layout still pushes one history snapshot for the position changes (existing `applyLayout` action behavior unchanged). (Spec AC4.4)

**Risk:** memory `reference_xyflow_setcenter.md` flagged the zoom-snap gotcha for `setCenter`/`setViewport`; `fitView` has different semantics (computes target zoom from bounds), so the gotcha does not apply. Verify at the manual-smoke stage with both small (3-node) and large (15-node) fixtures.

**Verification:**
- [ ] `npm run typecheck` green.
- [ ] Manual smoke (`npm run dev`): open `e2e/fixtures/multi-tree-with-subtree.json`, scatter Layout on each tab; each tab framed with comfortable padding.

**Dependencies:** None.

**Files:** `src/hooks/useApplyLayout.ts`.

**Estimated scope:** XS.

## T3 — Zoom-level chip in canvas (FB2)

**Description:** Add an xyflow `<Panel position="bottom-right">` inside `Canvas.tsx` containing a `<button>` showing the current zoom percentage. Subscribe to `onViewportChange` (or read the viewport store). Click resets zoom to 1.0 with 200ms easing, preserving x/y.

**Acceptance criteria:**
- [ ] Pill-shaped button labeled `N%` (rounded integer) appears bottom-right of the canvas. (Spec AC5.1)
- [ ] Label updates on wheel-zoom, pinch, programmatic zoom (e.g., from T2 Layout). (Spec AC5.2)
- [ ] Click → `setViewport({ x, y, zoom: 1 }, { duration: 200 })` preserving current x/y. (Spec AC5.3)
- [ ] Keyboard-focusable, `aria-label="Zoom: NN percent. Click to reset to 100%"`. (Spec AC5.4)
- [ ] Dark-mode tokens match existing `<Controls />` overlay styling. (Spec AC5.5)

**Risk:** the zoom value source must update reactively. Use either xyflow's `useViewport()` hook (preferred — built for this) or a viewport-store selector. Avoid `getZoom()` on each render (not reactive).

**Verification:**
- [ ] `npm run typecheck` green.
- [ ] Manual smoke (`npm run dev`): wheel-zoom in/out, observe label update; click chip → returns to 100% with smooth animation.

**Dependencies:** None.

**Files:** `src/components/canvas/Canvas.tsx`, optionally a small new `src/components/canvas/ZoomChip.tsx` if extraction is cleaner.

**Estimated scope:** S.

## T4 — `npm run preview` SW caching opt-out (B3)

**Description:** Add a `--mode no-pwa` guard in `vite.config.ts`'s plugin array; add a `preview:dev` script in `package.json` that runs `vite build --mode no-pwa && vite preview`; document the gotcha in README's troubleshooting section.

**Acceptance criteria:**
- [ ] `vite.config.ts` reads `mode` (via `defineConfig(({ mode }) => ({ ... }))`) and conditionally omits `VitePWA(...)` when `mode === 'no-pwa'`. Other modes (`development`, `production`) keep the plugin. (Spec AC3.1)
- [ ] `package.json` has `"preview:dev": "vite build --mode no-pwa && vite preview"`. (Spec AC3.2)
- [ ] `README.md` gains a small **Troubleshooting** subsection (or section) explaining: SW caches at `localhost:4173` after `npm run preview`; if logo/assets fail after killing preview, either run `npm run preview:dev` (no SW) or unregister via DevTools → Application → Service Workers. (Spec AC3.3)
- [ ] Original `npm run preview` continues to build with PWA + register SW for explicit PWA testing. (Spec AC3.4)

**Risk:** the `mode` flag changes vite behavior subtly — verify `npm run build` (no flag) still emits SW-enabled bundles. Don't break the production deploy path.

**Verification:**
- [ ] `npm run build` produces a SW-enabled bundle (verify `dist/sw.js` exists or `VitePWA`-injected script in `dist/index.html`).
- [ ] `npm run preview:dev` starts and the served HTML does **not** register a service worker (check DevTools → Application).
- [ ] Manual: run `npm run preview` in one terminal, hit `localhost:4173`, kill server, then run `npm run preview:dev` and confirm logo loads on `localhost:4173` (after a hard-refresh + SW unregister, or in an incognito window to bypass any pre-existing cache).

**Dependencies:** None.

**Files:** `vite.config.ts`, `package.json`, `README.md`.
