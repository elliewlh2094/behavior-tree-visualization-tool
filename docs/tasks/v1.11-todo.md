## 目標

讓使用者能在瀏覽器中透過公開網址開啟本工具，並提供精緻的登陸頁；另外加入四項編輯器內的易用性改善。分為兩個階段：

- **Phase A — Web Distribution（網頁發佈）：** FR3（登陸頁 + HashRouter）與 FR5（GitHub Pages 部署）。Phase A0（靜態資源路徑 + base）最先完成，因為子路徑 `base` 會讓所有絕對路徑的 `/asset` 在沒有錯誤訊息的情況下失效。
- **Phase B — In-Editor Usability（編輯器內易用性）：** FR6（搜尋）、~~FR7（小地圖）~~ **[移出範圍，AD9]**、FR8（範本）、FR9（未存變更守衛）。FR9 獨立；FR8 相依於 Phase A 的路由器與登陸頁。

## 已決議的規格決策

| # | 問題 | 決策 |
|---|---|---|
| 1 | **登陸頁與編輯器的串接方式** | `react-router-dom` **HashRouter**（AD7）。`#/` 為登陸頁，`#/editor` 為編輯器。選擇 HashRouter 而非 BrowserRouter 的原因：GitHub Pages 的深層連結完全沒有 404 風險；service worker 看不到 hash（對 PWA 安全）。 |
| 2 | **登陸頁元件** | 新的 `LandingPage.tsx`，**不是**改寫 `StartScreen`。**修訂（Checkpoint A 之後）：** `StartScreen` 已移除。LandingPage 取代它的品牌與入口角色；`#/editor` 直接進入畫布（store 預先建立 Root）；既有檔案由 Toolbar 的「Open」開啟。見 SPEC-v1.11 FR3 的修訂。 |
| 3 | **部署** | GitHub Actions → GitHub Pages，推送到 `main` 時自動部署。 |
| 4 | **base 路徑** | `command === 'build' ? '/behavior-tree-visualization-tool/' : '/'`，讓 dev 維持在 `/`。PWA 的 `start_url`／`scope` 維持 `'.'`。 |
| 5 | **搜尋範圍** | 只限使用中的樹（v1.11）。浮動的 Ctrl+F 搜尋列（jsoncrack 模型）。醒目標示使用獨特的外觀，不使用選取外框。 |
| 6 | **搜尋狀態** | 暫態的 store 欄位（`searchOpen`、`searchMatchIds`），排除在 `withSnapshot`／歷史紀錄之外（與 `exportInProgress` 相同的模式）。 |
| 7 | **範本儲存方式** | 以 v2 schema 序列化的 JSON 字串存放在 `src/templates/*.ts`，透過既有的 `deserialize → setDocument` 路徑載入（型別安全、打包進套件、不受 base 影響，不需要 fetch `public/*.json`）。 |
| 8 | **dirty 追蹤** | 訂閱 `document` **參照**的變化，並與 `lastSavedDocument` 比較（不在每個 action 中個別設定旗標）。涵蓋不經過 `withSnapshot` 的變更；沒有實際變更的 `return {}` 會保留參照，所以不會誤設 dirty。 |

## 不在範圍內（v1.11）

- 跨樹搜尋；regex／JSONPath 搜尋。
- BrowserRouter／不含 `#` 的乾淨網址（在 Pages 上需要 404.html 重新導向的權宜做法）。
- 命令面板、右鍵選單（已調查，延後；使用者未選擇）。
- 自動儲存／以 localStorage 持久保存文件（v1.11 以 dirty 守衛處理資料遺失風險）。
- 自訂網域。
