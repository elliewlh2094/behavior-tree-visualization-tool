# Todo: Behavior Tree Visualization Tool — v1.9 "Image Export"

## Objective

Add a single-action export of the currently active tree as a PNG image. Two modes: **transparent** (no background, no overlays) and **themed background** (current canvas bg color). Standalone feature — no coupling with v1.8 or v1.10. One new dependency (`html-to-image`).

## Resolved Spec Decisions

| # | Question | Decision |
|---|---|---|
| 1 | **Format** | PNG only at 2× pixel ratio. SVG explicitly out of scope per refined inventory. |
| 2 | **Library** | `html-to-image` (~14 KB gz, no peer deps, handles SVG-heavy DOM). Picked over `dom-to-image` (less maintained) and `canvas2html` (different API). |
| 3 | **Capture target** | The React Flow root element via `ref`. Pass to `toPng` with explicit `width`/`height`/`style.transform` derived from `getNodesBounds()` so the image contains the full tree, not just the visible viewport. |
| 4 | **Overlay handling** | Set a transient `exportInProgress: 'transparent' \| 'themed' \| null` flag on the store; `Canvas.tsx` and `BTNode.tsx` read it and conditionally hide `AxisOverlay`, `OriginCross`, the selection ring, and (transparent mode) `<Background>`. RAF wait between flag-set and capture so React commits the unmounts. |
| 5 | **Transient flag in undo?** | No. The flag is pure UI state, not in the unified timeline. |
| 6 | **Filename UX** | Default `<treeName>.png`; auto-append `.png` if missing (matches v1.1 file rename precedent). Browser default for collision handling (no overwrite warning needed in v1.9). |
| 7 | **Failure UX** | If `toPng` throws, modal stays open with inline error `Export failed: <message>`; flag clears via `try/finally`. |

## Out of Scope

- SVG export.
- Batch export of all tabs.
- Custom resolution / DPI selection.
- Title/legend/footer/watermark inclusion.
- Server-side rendering of the export.

## T2 — Conditional rendering when `exportInProgress` is set

**Description:** In `Canvas.tsx`, conditionally hide `AxisOverlay`, `OriginCross`, and (when `exportInProgress === 'transparent'`) the xyflow `<Background>`. In `BTNode.tsx`, suppress the selection `box-shadow` ring when `exportInProgress` is truthy. Forward a `ref` from `Canvas.tsx` to the React Flow root for T3's capture target.

**Acceptance criteria:**
- [ ] When `exportInProgress !== null`: `AxisOverlay` and `OriginCross` do not render. (Spec AC1.10)
- [ ] When `exportInProgress === 'transparent'`: xyflow `<Background>` does not render. (Spec AC1.7)
- [ ] When `exportInProgress` is truthy: `BTNode`'s selection `box-shadow` ring is suppressed (selected nodes still show but without the ring overlay). (Spec AC1.11)
- [ ] When `exportInProgress` is `null`: every visual is byte-identical to today.
- [ ] `Canvas.tsx` exposes a ref (or context) that T3 can read to find the React Flow root DOM node.

**Risk:** the suppression must apply on the next paint after the flag flips — verify React's render cycle commits before T3's capture call.

**Verification:**
- [ ] `npm run typecheck` green.
- [ ] Manual smoke (`npm run dev`): in DevTools console, set `useBTStore.setState({ exportInProgress: 'transparent' })`, observe overlays disappear; set back to `null`, overlays return. Repeat for `'themed'` (overlays gone but Background dots stay).

**Dependencies:** T1.

**Files:** `src/components/canvas/Canvas.tsx`, `src/components/canvas/BTNode.tsx`.

## T3 — `useExportImage` hook + `ExportImageModal` + Toolbar button

**Description:** Build the user-facing surface. New `useExportImage` hook encapsulates the flag-set → RAF wait → `htmlToImage.toPng()` → download → flag-clear flow. New `ExportImageModal` component matches the v1.4 T11 modal pattern (centered `<div role="dialog">`, Esc/backdrop dismiss, autofocus). New Toolbar button opens the modal.

**Acceptance criteria:**
- [ ] **Toolbar button:** new "Export image" button (icon + tooltip "Export tree as PNG"). Disabled when active tree has zero nodes (Spec AC1.2). Tooltip explains why when disabled.
- [ ] **Modal:** opens with mode toggle (default Themed), filename input prefilled `<activeTree.name>.png`, Export + Cancel buttons. (Spec AC1.3, AC1.4)
- [ ] **Filename:** Empty rejected (Export disabled). `.png` auto-appended if missing on Export. (Spec AC1.4, AC1.5)
- [ ] **Cancel paths:** Esc, click backdrop, Cancel button — all dismiss without action. (Spec AC1.6)
- [ ] **Capture flow** (in `useExportImage`):
  - [ ] Set `exportInProgress` to chosen mode.
  - [ ] `await new Promise(r => requestAnimationFrame(r))` — guarantees React paint.
  - [ ] Compute bounds via xyflow's `getNodesBounds()` from active tree's nodes.
  - [ ] Call `htmlToImage.toPng(target, { width, height, pixelRatio: 2, ... })`.
  - [ ] Trigger download via `<a download={filename}>` click pattern.
  - [ ] Clear `exportInProgress` in `finally` (so failure path also restores UI).
- [ ] Capture includes all nodes (Spec AC1.9).
- [ ] PNG dimensions are 2× the logical bounding box (Spec AC1.12).
- [ ] No history snapshot pushed (Spec AC1.13).
- [ ] On failure, modal stays open with inline error; flag clears (Spec AC1.15).

**Risk:**
- xyflow edges are SVG paths — `html-to-image` may need `cacheBust: true` or computed-style inlining for fidelity. Validate during this task.
- Position of the Toolbar button — slot it in a logical location (next to Validate, before the file name) and confirm during ship checkpoint.

**Verification:**
- [ ] `npm run typecheck` green.
- [ ] Manual smoke: build a 5-node tree → click Export image → modal opens → keep defaults → Export. Open the downloaded PNG. Verify nodes, edges, and (themed mode) background visible. Repeat with transparent mode and verify alpha channel.

**Dependencies:** T2.

**Files:** `src/hooks/useExportImage.ts` (new), `src/components/export/ExportImageModal.tsx` (new), `src/components/toolbar/Toolbar.tsx`.

**Estimated scope:** M.
