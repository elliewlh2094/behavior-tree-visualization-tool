# v1.8 – v1.10 Batch (post-v1.7.1)

## Problem Statement

How might we close out v1.7.1's user-reported papercuts and add the two cross-tree affordances (image export, Move/Copy between tabs) without bloating the SubTree identity model from v1.4 T9 or destabilizing the tab strip?

## Recommended Direction

Three small focused releases, each shippable on its own, in order of risk:

- **v1.8 — SubTree hardening & canvas polish.** Bug fixes (B1, B2, B3) plus the two zero-risk canvas tweaks (FB1 Layout-fits-tree, FB2 zoom display) and the PropertyPanel "Open subtree" button (FB4). Lowest risk; ships first to unblock real user pain.
- **v1.9 — Image export (FR1).** PNG export with transparent and themed-background modes. Standalone surface (Toolbar button → small modal). No coupling with anything else.
- **v1.10 — Cross-tree composition (FB3 + FR2).** Browser-style drag-to-reorder tabs (FB3) lands first so that v1.10's Move/Copy destination picker (FR2) lists tabs in user-meaningful order. Move/Copy is the highest-risk piece — it crosses the per-tab undo isolation that v1.7.1 unified into a single timeline.

**v1.6 (Repo Hygiene & Docs) slots between v1.8 and v1.9** — it's a pure cleanup release with zero behavior change, so interleaving it before v1.9 gives the repo a quiet checkpoint before adding the image-export dependency (html-to-image).

**Dropped from roadmap:** F17 (reusable node templates, AD5/v2.0) — user no longer wants. Update `docs/tasks/roadmap.md` accordingly.

**Deferred to a future batch:** FR4 (interop import/export to BehaviorTree.CPP, Groot, etc.) — nice-to-have, not urgent.

## MVP Scope per Release

### v1.8 — SubTree hardening & canvas polish

**In scope:**
- **B1.** SubTree node body renders the literal label "SubTree" + the referenced tree's name (no editable input). PropertyPanel for SubTree:
  - Read-only "References: TreeName" row.
  - Existing treeRef dropdown to swap reference (already shipped in v1.4 T8).
  - New "Open subtree ↗" button (FB4) that switches `activeTreeId` to the referenced tree. Disabled when no reference is set.
- **B2.** Investigate whether regular node names also push per-keystroke; if yes, change all editable name fields to commit-on-blur (Enter / blur / Escape semantics already established by v1.1 file rename T5).
- **B3.** Diagnose and fix or document the `npm run preview` logo issue. If it's a stale-cache problem with no real fix, remove `npm run preview` from `package.json` scripts and document `npm run dev` as the canonical local-verification command (the memory already recommends this).
- **FB1.** Layout button: keep `computeTreeLayout` re-positioning, but replace `setCenter(rootX, rootY) + getZoom()` with `fitView({padding: 0.2, duration: 200})`. Verify with the multi-tree fixture that tabs with different tree sizes all get the right framing.
- **FB2.** Display current zoom level as a small read-only chip in the bottom-right of the canvas (near the existing minimap area). Format: `N%` (e.g., `100%`, `42%`). Updates on every viewport change. Click resets to 100%.

**Out of scope:**
- Renaming a SubTree from anywhere other than the tab (double-click).
- Any change to the BTDocument data model or file format.
- Any change to the multi-select / duplicate behavior.

### v1.9 — Image export (FR1)

**In scope:**
- New Toolbar button "Export image" (icon + tooltip).
- Small modal with: mode toggle (Transparent | Themed background), filename input (default: current tree name `.png`), Export / Cancel buttons.
- PNG only @ 2× pixel ratio for retina.
- Transparent mode: hide Background dots, AxisOverlay, OriginCross during capture, restore on completion.
- Themed mode: render with current theme's canvas bg color (light = `--color-canvas-bg` light value, dark = dark value).
- Captures the *currently active* tree only — multi-tree export is out of scope.
- Captures the full tree bounds, not just the visible viewport.

**Dependency:** `html-to-image` (~14KB gzipped, no peer deps).

**Out of scope:**
- SVG export.
- Batch export of all tabs.
- Custom resolutions / DPI selection.
- Inclusion of legend, title, footer, watermark.

### v1.10 — Cross-tree composition (FB3 + FR2)

**FB3 — Tab reordering (lands first within v1.10):**
- Drag a tab horizontally to reorder. Reordering updates `BTDocument.trees` array order (the iteration order is what the tab strip renders today).
- Active tab indicator follows the moved tab; dropping outside the strip cancels (no detach-to-window).
- Single undo step per drop (use existing `withSnapshot`).
- Library: `@dnd-kit/sortable` (~9KB, accessibility-friendly) unless spec phase finds a smaller HTML5-DnD-only path.

**FR2 — Move/Copy (lands second):**
- New Toolbar button "Move / Copy" (active when ≥ 1 node selected).
- Modal:
  - Destination dropdown — lists all *other* tabs in current tab order (now stable thanks to FB3).
  - Mode radio: Move | Copy.
  - Summary: "N nodes, M edges, K edges to unselected nodes will be dropped".
  - Validation messages:
    - Disable destination if it already has a Root and selection contains a Root.
    - Disable destination if it would receive a SubTree node whose treeRef points to the destination itself (would create a cycle); show the inline reason.
  - Confirm / Cancel.
- Semantics:
  - **Move**: keep IDs; remove from source; add to destination; preserve relative positions.
  - **Copy**: regenerate IDs (reuse v1.5 `duplicateSelection` ID-mapping logic); leave source intact.
  - Boundary edges (selected → unselected) are silently dropped (v1.5 precedent in `ff64037`).
  - After completion, the destination tab activates and the newly-arrived/copied nodes are selected.
  - Single `withSnapshot` push covering both source and destination.

**Out of scope:**
- Drag-selection-onto-tab UX (deferred — modal is the primary surface).
- Cross-document (cross-file) move/copy.
- Smart-merge of edges to unselected nodes.

## Not Doing (and Why)

- **F17 / AD5 (reusable node templates)** — User decided it's no longer compelling. Deleting from roadmap rather than carrying dead weight.
- **FR4 (BehaviorTree.CPP / Groot interop)** — Nice-to-have, no urgent user pull. Each format is a substantial spec on its own (CPP XML grammar, Groot's quirks); will revisit after v1.10 if user demand grows.
- **SVG image export (in v1.9)** — Doubles the testing surface for a niche request. PNG covers ~95% of use cases (screenshots, slides, docs).
- **Custom Move/Copy keyboard shortcut (e.g., Ctrl+X / Ctrl+Shift+V)** — v1.5 explicitly avoided system-clipboard semantics. A modal-only entry point keeps the v1.5 precedent intact.
- **Renaming SubTree from PropertyPanel** — Single rename surface (tab double-click) is cleaner than two. Users who want to rename from the canvas can double-click the tab; they don't lose any capability.

## Open Questions (resolved during spec phase, not now)

1. v1.8 B1: When a SubTree's treeRef is *unset*, what does the node body show? Just "SubTree" with no second line? Or "SubTree" + dim placeholder "(no reference)"?
2. v1.8 FB2: Where exactly does the zoom chip go? Floating bottom-right is the natural xyflow convention, but we currently have AxisOverlay anchored differently — confirm during spec.
3. v1.9: Filename collision — overwrite warning, auto-suffix, or browser-default behavior?
4. v1.10 FR2: If Move would leave the source tree empty (no Root), is that allowed? My instinct is yes (empty trees are already creatable via the + button), but worth confirming.
5. v1.10 FB3: Drag handle — entire tab body draggable, or a dedicated grip area? Affects the rename interaction.
