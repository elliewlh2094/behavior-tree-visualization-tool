## Problem Statement

How might we let a first-time visitor understand and try the behavior-tree tool in a browser — without cloning a repo — and then navigate, search, and start from examples once inside the editor?

## Idea 4 — Survey & Convergence

Surveyed jsoncrack (44k★), Excalidraw (90k★), tldraw (45k★), React Flow, Rete.js (12k★), Groot2, Behavior3 Editor. Candidate features were filtered against **what the project already ships** (auto-layout via `useApplyLayout`, undo/redo unified timeline, image export, dark theme, validation, multi-tree). Only genuinely-new, high-ROI items remained:

- **Adopted:** Minimap (FR7), Example templates (FR8), Unsaved-changes guard (FR9 — user-added, the sharpest pain given file-only manual save).
- **Not adopted now:** Command palette (Ctrl+K), right-click context menu — surveyed, real value, but user did not select; deferred.
- **Rejected:** Real-time collaboration, share-by-link, live execution monitoring — out of the offline-first, no-backend design (monitoring is a compelling but large future direction, not v1.11).

## Recommended Direction

Ship as **one themed release (v1.11), two phases**: Web Distribution (FR3 landing + FR5 Pages deploy) then In-Editor Usability (FR6 search, FR7 minimap, FR8 templates, FR9 unsaved guard). Deployment foundation (asset paths + `base`) goes first because a subpath `base` silently breaks absolute `/asset` paths — a fail-fast risk.

Routing uses **HashRouter** (see `docs/adr/006`): on GitHub Pages project sites, deep links under a subpath 404 before the SW installs; the hash avoids that entirely and is invisible to the service worker, so PWA behavior is unchanged. The cost — a `#` in the URL — is acceptable for a free, domain-less deploy.

## Key Assumptions to Validate

- [ ] HashRouter + subpath `base` + PWA coexist — deep-link `…/#/editor` refresh and offline reload both work. *(Test: build + preview at subpath; incognito to dodge stale SW.)*
- [ ] No absolute `/asset` path survives the subpath migration — live logo + PWA icons render. *(Test: network tab on the deployed page.)*
- [ ] Dirty flag never misses a mutation (incl. non-`withSnapshot` `moveNode`/`updateNodeName`) and never false-positives on no-ops. *(Test: unit transitions; reference-equality is the mechanism.)*
- [ ] Ctrl+F can be intercepted without trapping the browser find inside text inputs. *(Test: `isEditableTarget` guard + `preventDefault`.)*
- [ ] Templates loaded via `deserialize → setDocument` validate clean and land as `dirty=false`.

## MVP Scope

In: FR3/FR5/FR6/FR7/FR9 fully; FR8 with 2 templates (Patrol, Chase). Out: cross-tree search, clean URLs, command palette/context menu, autosave/persistence, custom domain, BT-format interop (FR4 stays deferred).

## Not Doing (and Why)

- **BrowserRouter / clean URLs** — needs a `404.html` redirect hack on Pages; HashRouter is robust and free.
- **Command palette & context menu** — real value but not user-selected this round; revisit on demand.
- **Real-time monitoring / collaboration / share-link** — violate offline-first, no-backend; monitoring is a large standalone future bet.
- **Autosave / localStorage document** — the unsaved-changes guard (FR9) addresses the data-loss risk far more cheaply for v1.11.
- **Cross-tree search** — adds tab-switch + viewport-restore complexity; active-tree search covers the common case first.
