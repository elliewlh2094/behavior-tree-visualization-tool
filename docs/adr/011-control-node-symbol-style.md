# ADR 011 — 控制節點改為教科書式符號樣式

**日期：** 2026-11-19
**狀態：** 已接受

## 背景

v1.11 以前，9 種節點都畫成 150 × 75 px 圓角矩形，只有顏色與種類徽章不同。控制節點與執行節點的外形相同，讀者必須讀文字或辨認顏色才能區分。

Colledanchise & Ögren《Behavior Trees in Robotics and AI》（2018）的畫法是：控制節點畫成小方框，方框內只有符號（Sequence →、Fallback ?、Parallel ⇉），Decorator 畫成菱形並在旁邊標示策略。使用者認為這種畫法讓讀者更容易區分節點，也讓編輯者不必替控制節點命名。

現有排版把父節點的 x 設為子節點左上角 x 的平均值。這個算法隱含「所有節點等寬」的假設；控制節點縮小後，這個假設不再成立。

## 決策

1. **Sequence、Fallback、Parallel 畫成 50 × 50 px 符號方框**，畫布與匯出 PNG 都不顯示名稱與種類徽章。
2. **Decorator 畫成 50 × 50 px 菱形（內含 δ），名稱顯示在右側。** App 沒有 Decorator 子類型，Decorator 的語意只存在於名稱中，所以名稱必須保留顯示。標籤屬於節點外框，所以匯出取景與點選範圍都包含標籤；Handle 固定在菱形中心。
3. **其他種類不變。** Action、Condition 不改外形，以免壓縮文字空間；顏色已足以區分它們。Root、Group、SubTree 是 App 特有的種類，書中沒有對應符號；Group 承擔標籤功能。
4. **排版以錨點置中。** `computeTreeLayout` 接收每個節點的錨點（左緣到中心線的距離），父節點置中於子節點中心線的平均值。不提供錨點時，結果與舊算法相同。
5. **搜尋不比對 Sequence、Fallback、Parallel 的名稱。** 畫布上看不到這些名稱，綠色搜尋外框會讓使用者找不到符合的文字。
6. **直接取代舊樣式，不提供切換開關。** 開關會讓兩套樣式在排版、匯出與測試中並存。
7. **JSON 格式與 `name` 欄位不變。** Properties 面板仍可編輯名稱，舊檔案不遺失資料。

## 考慮過的替代方案

| 方案 | 不採用的原因 |
|---|---|
| 節點外框維持 150 px 寬，只在中央畫小方框（排版不改） | 留下 150 px 寬的隱形點選區域；Decorator 標籤只剩約 50 px 空間。 |
| 只在匯出時改用教科書樣式 | 使用者認為新樣式在編輯時也更容易閱讀。 |
| 只改 `BTNode`，排版不改 | 父節點偏左 50 px，連線歪斜。 |
| 在控制節點旁顯示名稱標籤 | 圖片不再符合教科書畫法，標籤也會佔用寬度。需要標籤時改用 Group。 |

## 影響

- **舊檔案的座標不自動遷移。** 控制節點以舊的左上角座標繪製，看起來會偏左；按 Layout 即可重新對齊。自動遷移會讓剛開啟的檔案變成 dirty，所以不採用。
- **長期方向：** 控制節點名稱沒有畫布用途。之後的大版本可以移除名稱編輯（已列入 roadmap Deferred）。
