# ADR 012 — 新增緊密排版模式

**日期：** 2026-11-19
**狀態：** 已接受

## 背景

`computeTreeLayout`（AD3）讓每個葉節點佔一個 `nodeWidth + gapX`（200 px）的欄位，不論葉節點位於哪一列。所以樹的寬度與葉節點數量成正比，大型樹在展示時需要大幅縮小。

Colledanchise & Ögren《Behavior Trees in Robotics and AI》（2018）圖 7.8 的樹依子樹輪廓緊貼排列：一個深的子樹可以伸到淺的兄弟子樹下方，兄弟之間的空白也很小。使用者希望保留現有排版，另外提供接近書中樣子的選項。

## 決策

1. **新增偏好 `layoutMode`（`'default' | 'compact'`，預設 `'default'`）。** 偏好放在 preferences store（AD1），Settings 面板以 Default／Compact 切換。排版模式是展示偏好，不屬於文件，所以 JSON 格式不變。
2. **切換偏好不重新排版。** 排版會覆蓋手動位置；偏好不參與 undo，若切換偏好就改寫文件，會混淆「偏好」與「文件編輯」。使用者下次按 Layout 才生效，那次排版可以 undo。
3. **Default 模式不變。** `computeTreeLayout` 的 `mode` 參數預設為 `'default'`，原有程式路徑不修改。
4. **Compact 模式以輪廓壓縮（Reingold–Tilford）定位兄弟子樹。** 每個子樹記錄每一相對深度的左右邊緣；新子樹只與已放置子樹共同存在的深度比較，間距 `gapX = 25`（1 格）。
5. **兄弟子樹以左右兩趟取平均定位。** 只由左向右放置時，夾在兩個大子樹之間的小子樹會擠向左側。兩趟取平均讓樹保持鏡像對稱。
   - 不重疊的理由：每一對兄弟子樹的限制都是 `x_j − x_i ≥ d_ij` 形式的差分不等式，可行解集合是凸集合。由左向右得到一個可行解，由右向左得到另一個可行解，兩者的平均值也是可行解。
6. **Compact 模式使用節點的量測寬度。** v1.12 起 Decorator 含標籤時寬度不固定（AD11）；以固定寬度計算會讓標籤與相鄰節點重疊。
7. **列距維持 50 px。** 書中列與列之間的空白約等於節點方框的高度；目前列距 50 px、節點高 75 px，已經比書中緊密。大型樹的問題是寬度。

## 考慮過的替代方案

| 方案 | 不採用的原因 |
|---|---|
| 只縮小 `gapX` | 寬度仍與葉節點數量成正比，無法讓深子樹伸到淺兄弟下方。 |
| 只由左向右放置（經典 Reingold–Tilford） | 小子樹擠向左側，樹不對稱。 |
| Walker／Buchheim 演算法或 d3-hierarchy | d3.tree 假設等寬節點；自製 Walker 約 150 行。兩趟平均以約 20 行達到對稱，且符合 AD3 自製排版的決策。 |
| 排版模式存進文件 | 需要修改檔案格式；模式是展示偏好，不是樹的內容。 |
| 列距也縮小到 25 px | Bezier 連線在多子節點時接近水平，較難辨認；書中的列距也沒有比現在更小。 |

## 影響

- 平均後的子樹偏移與父節點中點可能落在半格，最後的格線貼齊讓每個節點最多移動 12.5 px。間距是 25 px，所以貼齊後相鄰節點可能相接，但不會重疊。
