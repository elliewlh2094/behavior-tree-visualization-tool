## Objective

Add a **duplicate-selection** action so authors can fork-and-diverge tree structures inside a single tree. The multi-selection infrastructure (Shift+Click, Box-select, Ctrl/Cmd+A, multi-selected visual feedback, atomic `deleteSelection`) already shipped in v1.4 Phase 2 — v1.5 adds only the duplicate operation behind `Ctrl/Cmd+D` plus the pure tree-level helper that powers it.

## Resolved Spec Decisions

| # | Question | Decision |
|---|---|---|
| 1 | **Offset direction + magnitude** | `(GRID_SIZE, GRID_SIZE)` = `(25, 25)` — one grid step right + down. Keeps duplicates grid-aligned and immediately visible. |
| 2 | **Empty / edges-only / Root-only selection** | All no-ops — no history snapshot, no state change, no toast. Ctrl+D is silent when there's nothing to duplicate. |
| 3 | **Root inclusion** | Root filtered out silently (only one Root per tree). If a selection of `{Root, Action}` is duplicated, only the Action is. If the entire selection was `{Root}`, it's a no-op. |
| 4 | **SubTree handling** | `treeRef` preserved on the duplicate (the duplicate references the same target tree). Falls out of cloning the node fields. |
| 5 | **Connection `order` for duplicates** | Preserved as-is. Duplicates land orphaned (no edge from any non-selected parent into the set), so there is no sibling-renumbering ambiguity. |
| 6 | **Selection after duplicate** | New selection becomes the duplicated set so the user can immediately drag, delete, or re-duplicate. Original selection is cleared. |
| 7 | **Keyboard binding** | `Ctrl/Cmd+D` only. The originally-proposed `Ctrl+C → Ctrl+V` alias was dropped — without cross-tab clipboard or system-clipboard integration, it would be cargo-cult copy-paste. Browser default Ctrl+C still works for text copy inside text inputs (we don't override it). |
| 8 | **Cross-tab interaction** | Ctrl+D acts on the active tree only. Selection is scoped per active tree (T9 of v1.4 already clears selection on tab switch), so the question is moot. |

## Out of Scope

- Cross-tab paste / system-clipboard integration
- Drag-with-Alt to duplicate (different gesture; not on the roadmap)
- Multi-selection rubber-band behavior (already shipped via xyflow `multiSelectionKeyCode` in v1.4)
- Cross-tree-mutation undo for duplicate (duplicate is a single-tree mutation; F19 doesn't apply)

## T1 — `duplicateSelection` pure operation ✅ Done (2026-05-08)

**Description:** New pure tree-level function in `src/core/model/operations.ts` that produces a new `Treeish` with the selected nodes duplicated (Root excluded) and the edges *among* the selected set copied with fresh ids. Mirrors the `addNode` / `removeNode` / `connect` precedent.

**Signature:**
```ts
export function duplicateSelection<T extends Treeish>(
  tree: T,
  nodeIds: ReadonlySet<string>,
  options: { offsetX: number; offsetY: number },
): { tree: T; newNodeIds: Set<string>; newEdgeIds: Set<string> };
```

**Plan deviation (surfaced):** the spec's draft signature included an `idGen: () => string` injection for deterministic test ids. Dropped during implementation to match `addNode` / `connect` precedent (both call `crypto.randomUUID()` directly). Tests assert structural properties (count, position offset, presence in `newNodeIds`, no id collisions) instead of exact id values, which is enough.

**Acceptance criteria:**
- [x] Filters Root and unknown ids out of `nodeIds` before processing.
- [x] Returns the input tree by reference (same object identity) when there is nothing to duplicate after filtering. `newNodeIds` and `newEdgeIds` are empty in that case.
- [x] Each duplicated node gets a fresh id (`crypto.randomUUID`). Position is `original.position + (offsetX, offsetY)`.
- [x] All other node fields are deep-copied verbatim — including `treeRef` on SubTree nodes (preserved unchanged); `properties` shallow-copied per existing convention.
- [x] Connections **among** the duplicated set are copied with new ids and remapped `parentId` / `childId`. `order` values are preserved as-is.
- [x] Connections crossing the boundary (selected child ↔ unselected parent, or selected parent ↔ unselected child) are dropped — duplicates land orphaned-in-place.
- [x] `newNodeIds` and `newEdgeIds` expose the duplicated set so the store action can swap selection.

**Verification:**
- [x] Unit tests in `tests/unit/core/model/operations.test.ts` (+11 new tests in a `describe('duplicateSelection', …)` block): empty selection no-op, Root + unknown filtered, single-node duplicate with offset, connected pair preserves the among-set edge, boundary edges dropped (both directions), edge `order` preserved, originals untouched, SubTree `treeRef` preserved, no input mutation, no id collisions.
- [x] `npm run typecheck` green.
- [x] Full unit suite: 326 → 337 (11 added).

**Dependencies:** None.

**Files:** `src/core/model/operations.ts`, `tests/unit/core/model/operations.test.ts`.

**Estimated scope:** M.

## T2 — Store `duplicateSelection` action

**Description:** Wrap T1 in a single store action that snapshots history once via `withHistory`, replaces the active tree, and updates `selection` to the duplicated set.

**Acceptance criteria:**
- [ ] New action `duplicateSelection: () => void` on `BTStoreState`.
- [ ] Reads active tree (`selectActiveTree(state)`) and `state.selection.nodeIds`.
- [ ] Calls `duplicateSelection` (T1) with `offsetX = offsetY = GRID_SIZE` (imported from `src/core/config/grid.ts`) and `idGen = () => crypto.randomUUID()`.
- [ ] Wraps the result with `withHistory(state, prevTree, nextTree, { selection })` — single undo step.
- [ ] When T1 returns the same tree by reference (nothing duplicated), the action returns `{}` so no history snapshot is pushed and selection is untouched.
- [ ] On success, `selection` becomes `{ nodeIds: result.newNodeIds, edgeIds: result.newEdgeIds }` — original selection is cleared.

**Verification:**
- [ ] New unit test file `tests/unit/store/bt-store-duplicate.test.ts`:
  - Happy path: 2 nodes selected → duplicate → 4 nodes + correct selection swap; one undo restores the pre-duplicate state.
  - Empty selection → no-op (no history push, undo stack length unchanged).
  - Edges-only selection → no-op (no nodes to duplicate).
  - Root-only selection → no-op.
  - Selection containing Root + others → only the others duplicate; selection becomes the duplicated set (no Root).
  - SubTree-with-treeRef in selection → duplicate preserves `treeRef`.
- [ ] Existing 326 unit tests still pass.

**Dependencies:** T1.

**Files:** `src/store/bt-store.ts`, `tests/unit/store/bt-store-duplicate.test.ts` (new).

**Estimated scope:** S.

## T3 — Ctrl/Cmd+D keyboard handler

**Description:** Wire `Ctrl/Cmd+D` to dispatch the store's `duplicateSelection` action. Reuse the editable-target guard pattern from the existing Ctrl+A handler so text inputs (file rename, property-panel name, tab rename) keep their natural behavior. **Do not** add Ctrl+C or Ctrl+V handlers.

**Acceptance criteria:**
- [ ] `Toolbar.tsx` (or wherever the existing keyboard switch lives) gains a `case 'd'` branch in the `(ctrl||meta) && !shift && !alt` switch.

- [ ] `event.preventDefault()` to swallow the browser's default Ctrl+D ("bookmark this page" in Chrome/Firefox).
- [ ] Both `Ctrl+D` and `Cmd+D` (macOS) trigger the same action.
- [ ] No Ctrl+C / Ctrl+V handler added — browser default behavior preserved.

**Verification:**

  - `Ctrl+D` while focused inside an `<input>` does NOT dispatch (editable-target guard).
- [ ] Manual smoke: in dev (`npm run dev`), select two nodes on a tree → press Ctrl+D → duplicates appear at +(25, 25) → press Ctrl+Z → original state restored.
